# Tech Context

## Stack
Python 3.12: Flask + gunicorn for `vote`/`result`, plain Python for `worker`. Redis (queue), Postgres (result store). Kubernetes via kustomize, deployed to k3d on macOS arm64. Base image `python:3.12-slim`, built `linux/arm64`.

## Commands
- Install: `pip3 install -r vote/requirements.txt` for local dev; no repo-level install step.
- Build: `./scripts/build.sh` — `docker build --platform linux/arm64` + `k3d image import`. Registry mode: `REGISTRY=1 ./scripts/build.sh`.
- Deploy: `./scripts/deploy.sh` — creates k3d cluster if missing, builds, applies kustomize, waits for rollouts.
- Verify: `./scripts/verify.sh` — runs R1–R17, appends results to `.workflow/verify.md`.
- Lint: none configured; bash scripts use `set -euo pipefail`.
- Run locally: needs k3d + docker + kubectl (all present). See `docs/SCRIPTS-GUIDE.md`.

## Dependencies
Non-obvious: images are `linux/arm64`-only and must be imported into the k3d cluster (no registry unless `REGISTRY=1`). `kustomize/postgres-secret.env` holds Postgres creds + Flask `SECRET_KEY` (gitignored, generated by deploy.sh). Postgres pod name is stable (`<release>-postgres-0`) for verify.sh's `psql` exec.

## Constraints
macOS arm64 only; k3d cluster named `voting-app`; Ingress on host ports 8081 (HTTP) / 8082 (HTTPS); no NodePort; hostnames use the `.localhost` TLD which resolves to 127.0.0.1 natively (RFC 6761) — no /etc/hosts, no external DNS.

## Do not touch
`kustomize/postgres-secret.env` (credentials), `__pycache__/`, and `.gitignore`d tool artifacts (`.omo/`, `.antigravitycli/`, `.agents/`).
